# Sheaft v1.3.0

`v1.3.0` adds endpoint-specific component criticality using Birnbaum importance. It ranks how strongly service liveness and edge connectivity affect each selected operation, with paired counterfactual trials and explicit statistical uncertainty.

The release remains within the v1 semantic boundary documented in [docs/v1-major-semantics.md](https://github.com/MB3R-Lab/Sheaft/blob/v1.3.0/docs/v1-major-semantics.md).

## Added

- opt-in Sheaft analysis schema `1.3` with `importance[]` requests referencing an independent baseline profile
- forced-up and forced-down component evaluation on the same trial world and execution randomness
- per-endpoint service and edge rankings, two-sided Wilson intervals, and pivotal trial counts
- baseline component live probability, forced-down impact, and perfect-component gain
- explicit component subsets and report-only `top_k` truncation
- JSON importance schema and component-criticality tables in `summary.md`
- runnable `configs/analysis.importance.example.yaml` in the default config pack
- closed-form series/fallback, replication, async semantics, retry, and CLI regression evidence

## Product workflow

Use the ranking to identify operation bottlenecks and select candidate reliability improvements or chaos experiments. Check both importance and perfect-component gain: an already near-perfect component can be structurally critical while offering little additional reliability gain.

Ranks use point estimates. Overlapping intervals do not establish a statistically reliable ordering. Confidence is conditional on the configured model and does not certify topology discovery or probability calibration. See [docs/component-criticality.md](https://github.com/MB3R-Lab/Sheaft/blob/v1.3.0/docs/component-criticality.md).

## Compatibility and fixes

Analysis schemas `1.0`, `1.1`, and `1.2` remain accepted. Existing profile and boundary gates retain their behavior; importance is explanatory output and is not averaged into gate availability. Schema `1.3` belongs to Sheaft and is separate from the Bering `1.3.0` model/snapshot contracts, whose pins remain unchanged.

Baseline sampling now also honors explicit `failure_eligible: false` metadata. Protected services stay live and are excluded from fixed-k sampling populations. Explicit criticality counterfactuals can still force a selected protected service down, revealing its structural impact.

## Boundaries

Classical Birnbaum requests require independent service or replica sampling without a fault overlay. For replicated services, importance is a derivative with respect to aggregate service availability, not a per-replica probability or replica-count derivative. Edge importance concerns binary connectivity rather than the observed per-request error rate.

Group/zone importance, automatic importance regression gates, capacity feedback, automatic probability calibration, arbitrary non-product `P`, live chaos execution, and rich temporal workflow models remain outside this release.
