# Sheaft v1.3.1

`v1.3.1` adds explicit mandatory-call obligations to an `edge_aware` endpoint
predicate. Reachability alone can admit a surviving alternative path when a
particular call must succeed. External predicate contract `1.1` can now name that
call using its exact Bering edge ID.

The release stays within [the v1 semantic boundary](https://github.com/MB3R-Lab/Sheaft/blob/v1.3.1/docs/v1-major-semantics.md).

## Changes

- Optional `required_edges` conjunctively requires selected calls in addition to
  mandatory-target reachability. Both endpoints must be live, and the caller
  must remain reachable in the sampled state.
- Unknown edges, unsupported edge modes, duplicate/empty IDs, and topologically
  unreachable callers are rejected explicitly.
- Availability, sweeps, and paired Birnbaum importance share the same predicate.
- A runnable required-call example is included in the default config pack and
  checked by release smoke tests.
- README, configuration/consumer documentation, and the compatibility matrix
  distinguish predicate, analysis, and upstream schema versions. Gate docs
  distinguish point estimates, pointwise Wilson certification, and discrete
  certified-metric regression.

## Compatibility

Existing predicate contract `1.0` and analysis schemas `1.0` through `1.3` retain
their behavior. Opt into predicate contract `1.1` only when required calls are
needed. Contract `1.0` rejects nonempty `required_edges`; older Sheaft releases
reject contract `1.1` rather than silently dropping the condition. Bering model
and snapshot schema `1.3.0` URIs and digests are unchanged.

## Verification and limits

Tests enumerate all eight channel states of a two-path triangle, check unknown
edges and disconnected callers, and compare availability and nontrivial service/
edge Birnbaum values with independent series-system formulas. Tag CI runs the
test suite, packaged examples, release-asset validation, and fixed quality slice.

Required calls do not express call order, arbitrary payload/cache behavior,
temporal recovery, or capacity feedback. Fail-stop channel state is shared by
repeated RPCs in a trial. Handler correspondence and operational probabilities
remain explicit application-specific assumptions, not inferred guarantees.
